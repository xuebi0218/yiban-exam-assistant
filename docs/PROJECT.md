# 形势与政策答题助手 — 项目文档

> 版本：v3（浏览器保活版） · 更新：2026-10-23

---

## 一、项目概述

面向「易班优课（yooc.me）形势与政策考试」的作答辅助系统。
核心能力：**题库命中即秒答，未命中则遍历电子教材求解，全程可视化操作。**

### 自动化边界

| 环节 | 自动化 |
|---|---|
| 登录（Cookie → SSO） | ✅ 全自动 |
| 打开考试页 | ✅ 全自动 |
| 拉取试卷 | ✅ 全自动 |
| 生成答案（题库/教材） | ✅ 全自动 |
| 填写到网页 | ✅ 全自动 |
| 三道门禁校验 | ✅ 全自动 |
| **人机验证** | ❌ 人工（数美/网易易盾，无法绕过） |
| **点交卷** | ❌ 人工（不可逆，防误交） |

## 三、核心模块

### 3.1 登录层

| 文件 | 职责 |
|---|---|
| `yiban_sso.py` | 用 `yiban_user_token` 走官方 SSO 换优课三项凭证 |
| `login.py` | Cookie 粘贴 / 账号密码 / 凭据校验 |
| `qr_login.py` | 易班 App 扫码登录（线程安全封装） |
| `scan_to_yooc.py` | 扫码 → SSO → 开考试页 一体化 |

**SSO 机制（实测确认）**

```
https://www.yooc.me/yiban_account/sso?access_token=<yiban_user_token>
  → 302 + Set-Cookie: user_token / yiban_id / user_id
```

两个必须注意的实现细节：

1. **必须 `allow_redirects=False`** —— 三项 `Set-Cookie` 只存在于那个 302 响应头，
   自动跟随会被吞掉，表现为「成功但没 token」。
2. **只需要 access_token** —— 早期误判为「必须带完整 yiban cookie」，
   实为上述重定向问题所致。

### 3.2 答案引擎（`answer_engine.py`）

**分层策略**

| 层级 | 条件 | 处理 | 实测准确率 |
|---|---|---|---|
| L0 题库 | 题干归一化命中 | 直接采用 | **100%** |
| L1 教材·自动 | 置信 ≥ 0.90 | 自动填入 | **98.6%** |
| L2 教材·待复核 | 0.70 ~ 0.90 | 采用并标黄 | ~88% |
| L3 低置信 | < 0.70 | **不填** | — |

**教材求解原理：双向夹逼**

```
教材：…防范化解重点领域风险，房地产领域，核心在于稳市场、保民生。…
                        ↑答案      ↑suffix 锚点
题干：防范化解重点领域风险，{input}，核心在于稳市场、保民生。
                        ↑prefix        ↑suffix
```

1. `suffix` 在教材中定位（要求唯一命中）
2. `prefix` 向左对齐左边界
3. 两者之间即答案

**修复的三类系统性缺陷（v1 → v2，+12pp）**

| 缺陷 | 现象 | 修法 |
|---|---|---|
| 填空溢出 | 答案带 `"` 或跨句粘连 | `clean_answer()` 剥离引号句读 |
| 判断题全错 | 12/12 真答案皆「对」，旧逻辑判「错」 | 分块覆盖率 + 缺证据倾向「对」 |
| 多选漏选 | 窗口 620 字、阈值一刀切 | 窗口 1600 字 + 完备性回补 |

### 3.3 浏览器保活（`browser_keeper.py`）

**修复的核心痛点**

旧实现每次操作都 `launch → close`，导致：

- 每次全新 context，会话不共享 → **人机验证反复过**
- 窗口开了又关 → 观感差
- 流程结束关闭浏览器 → **无法人工交卷**

**现架构**

```
全局单例 BrowserKeeper
  · 一条专属工作线程（Playwright 有线程亲和性）
  · 首次操作时打开，之后全部复用
  · 流程结束保持打开，留给人工交卷
  · 只有显式 close() 才真正关闭
```

**验证**：连续多次操作后 `uptime` 单调递增（28→31→34→36s），
证明始终是同一浏览器实例。

### 3.4 编排层（`orchestrator.py`）

负责：题库优先 → 教材兜底 → 标记复核 → 输出填写指令。
置信度阈值经 200 题实测校准（阈值改动前必须跑评测）。

## 九、踩过的坑（供后续维护）

| 坑 | 现象 | 根因 |
|---|---|---|
| SSO「成功但没 token」 | 200 空响应 | 自动跟随 302 吞掉 Set-Cookie |
| 登录被误判有效 | 任意 token 都 result:true | `user/check` 是宽松接口 |
| Playwright 跨线程崩溃 | `Cannot switch to a different thread` | 同步对象有线程亲和性 |
| 扫码「没反应」 | 码秒过期 | 二维码有效期仅 60s，需自动续码 |
| 人机验证反复过 | 每次操作都过验证 | 每操作单独 launch 浏览器（已改保活） |
| 无法人工交卷 | 流程结束浏览器被关 | finally 里无条件 close（已修） |
| urllib 忽略 Cookie | SSO 拿不到会话 | `opener.open` 覆盖自定义头，改用 requests |
| 浏览器停在 about:blank | 开窗后空白，看不到任何页面 | `open` 只 ensure 未导航（已修，现自动进考试列表页） |
| 单例跨进程失效 | 独立脚本里 `get_keeper()` 报 `_q is None` | 单例只在**服务进程内**有效，外部脚本是另一个实例 |

## 十、维护指引

1. **改答案算法前**：先跑 `eval_engine.py` 记录基线
2. **改置信度阈值**：必须同时看准确率与覆盖率，不能只看一个
3. **题库异常**：`qbank.py conflicts` 应恒为 0，出现即需人工裁定
4. **登录失效**：`yiban_sso.py --check` 会走业务接口给出真实结论
5. **不要**在 `finally` 里无条件 `ctx.close()`
